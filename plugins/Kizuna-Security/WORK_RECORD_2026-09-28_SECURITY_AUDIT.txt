■ 検出したバグと修正
================================================================

[1] 【重大/検知バイパス】ベースライン時に存在しない監視対象ファイルの
    「作成」を見逃す (fim.go)

  症状:
    既定の監視対象には通常存在しないファイルが含まれる
    (例: /etc/ld.so.preload, /root/.ssh/authorized_keys)。
    初回ベースラインで hashFile が失敗したファイルは baseline にも
    watched にも記録されない。その後、攻撃者が当該ファイルを作成すると、
    Check() は「存在しない→存在する」を「監視対象に新規追加された」と
    誤判定し、watched[p]==false のため無言でスキップ(continue)する。
    結果、バックドア作成(例: /etc/ld.so.preload による rootkit ロード)を
    一切検知できなかった。

  修正:
    saveBaselineLocked() の先頭で、設定された全監視対象(f.files)を
    「既知(watched)」に登録する。初回・通常時・ベースライン再保存の
    すべての経路で、存在しないファイルも既知として扱われるようになる。
    これにより、後から作成されたファイルは正しく critical「作成」として
    検知される。

  回帰テスト:
    fim_regression_test.go
      TestFIMDetectsCreateOfFileMissingAtBaseline
      (ベースライン時に不在 → 後から作成 → critical 検知を検証)

  ※ 既存の TestFIMNewWatchTargetSilent(監視対象を意図的に追加した場合は
     無言でベースライン化) は維持され、誤警報防止の挙動は壊していない。

■ 確認のみ (問題なし・変更不要と判断)
================================================================
  - config.go: watch_files は絶対パスの .log のみ、log_path は .log のみ、
    '..'/NUL/改行を拒否。integrity_files は絶対パス必須。
    block_whitelist は IP/CIDR 検証、各上限(64/256/1024件)あり。
  - monitor.go: O_NOFOLLOW でシンボリックリンク追跡を防止。通常ファイル
    限定。部分行(改行なし)を消費しない ReadBytes 方式で検知漏れを防止。
    failCounts 上限 10000、queue 上限 1000、1回の読み取り 512MB、
    1スキャン 100000 行。重複行デデュープ、CRITICAL は1回のみ通知。
  - blocker.go: sudo/iptables は絶対パス解決(PATH ハイジャック対策)、
    exec.Command に固定配列(シェル非経由)、isValidIPArg で引数インジェク
    ション防止。ループバック/リンクローカル/不正IP/ホワイトリストは
    ブロックしない。失敗時は blocked に記録せず誤認防止。上限 10000。
  - fim.go: SHA-256、O_NOFOLLOW、通常ファイル限定、ベースラインは
    0600 + 一時ファイル + rename で原子的保存。旧形式の後方互換あり。
  - logger.go: 各行に prev_hash/hash のハッシュチェーン。VerifyChain で
    改ざん検出。破損ログは .legacy-<日時> に退避しチェーンを再開始。
    0600 / ディレクトリ 0700 / O_NOFOLLOW。
  - plugin.go: 設定は p.mu で保護。再 Configure 時は旧 FileLogger を Close。

■ ビルド & 配備手順
================================================================
  1) 本体 Kizuna-Eye を再ビルド (pkg/module 変更時は必須)
       cd /samba/share/Kizuna-Eye && ./build.sh
  2) プラグインを同一ソースで再ビルド
       cd /samba/share/Kizuna-Security/plugin
       GOWORK=off CGO_ENABLED=1 go build -buildmode=plugin -o kizuna_security.so .

  4) agent を再起動

  同一ソースから同時再ビルドすること(plugin のハッシュ一致制約)。
