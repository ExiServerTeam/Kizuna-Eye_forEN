# 作業記録: バグ調査・修正（2026-09-27 / 2026-09-28）

本書は、Kizuna-Eye 本体に対して行ったバグ調査と修正の記録である。
対象期間は 2026年9月27日および9月28日で、実施者は AI（webcode）である。

---

## 1. 作業の目的

利用者からの依頼は次のとおりであった。

- バグおよびセキュリティホールを徹底的に調査し、確実に塞ぐこと。
- 仕様書と既存の作業記録を読んだうえで作業し、実施内容を記録に残すこと。
- テストを繰り返し実行し、修正が回帰を起こしていないことを確認すること。

## 2. 基本方針

調査と修正は、次の方針に従って実施した。

- Agent（`role=agent` かつ正しいトークンを持つ接続）以外は、すべて信頼できない入力元として扱う。
- 権限は README の権限表（viewer = 閲覧のみ、operator = 運用操作、admin = 全権）に厳密に一致させる。
- 既存の防御機構（`CheckOrigin`、ボディサイズ制限、`role=agent`、`isLoopback`、ファイル権限 0600/0700 など）は維持する。
- 修正には必ず回帰テストを添える。

## 4. 9月27日に検出・修正した問題

### 4.1 コアロジック

1. **Agent 接続の乗っ取り**（`cmd/dashboard/main.go`）
   ブラウザが `{}` などの任意の JSON を送信すると、それが `SystemStatus` として解釈され、Agent 接続として扱われていた。その結果、本物の Agent 接続が上書きされ、以後のコマンドが誤った接続へ送信される恐れがあった。タイムスタンプが 0 以下のペイロードは Agent とみなさないよう修正した。

2. **`OnStatus` の nil ガード欠落**（`pkg/alert/engine.go`）
   引数が nil の場合に panic する可能性があったため、冒頭で nil チェックを追加した。

3. **`Notify` の nil ガード欠落**（`pkg/notify/manager.go`）
   同様に nil チェックを追加した。

4. **ログローテーションの誤削除**（`pkg/logger/logger.go`）
   ローテーション後のファイルを文字列でソートしていたため、`app.log.10` を `app.log.2` より古いと誤判定し、回転が 10 回を超えると最新のログを削除していた。数値サフィックスを数値として比較するよう修正した。

### 4.2 API とフロントエンド

5. **Windows パスの未対応**（`cmd/plugin-inspect/main.go`）
   プラグイン名の抽出が `/` のみを区切りとしており、Windows のフルパスがそのまま名前になっていた。`\` も区切りとして扱うよう修正した。

6. **SSE の読み取り位置ズレ**（`internal/api/logs.go`）
   `bufio.Scanner` が行末の `\r` を除去するため、CRLF のファイルで読み取り位置が 1 バイトずれ、ログ行の重複や欠落が発生していた。実バイト数を数える方式に変更した。

7. **空き容量パーセントのクランプ**（`pkg/alert/engine.go`）
   値が 0〜100 の範囲を外れる場合にクランプするよう修正した。

8. **折りたたみボタンのスコープ誤り**（`web/static/app.js`）
   セレクタが最初に一致する要素（履歴セクション）を指しており、プラグインの折りたたみで誤ったボタンを操作していた。対象をスコープ内に限定した。

9. **存在しない JavaScript の読み込み**（`web/static/config-editor.html`）
   存在しない `auth-guard.js` を読み込んでいたため、404 が発生していた。タグを削除した。

### 4.3 推奨事項への対応

10. **接続ごとの書き込みロック**（`cmd/dashboard/main.go`）
    以前は全クライアントで 1 つの書き込みロックを共有しており、遅いクライアントが全体をブロックしていた。接続ごとにロックを持つ構造へ変更した。

11. **通知の同時実行数制限**（`pkg/notify/manager.go`）
    通知ごとに無制限で goroutine を生成していたため、障害時に急増する恐れがあった。同時実行数を 32 に制限し、飽和時は送信をスキップして警告を記録するようにした。

12. **設定保存のアトミック化**（`internal/api/config.go`）
    `os.WriteFile` は非アトミックであり、書き込み中にクラッシュすると設定が破損する恐れがあった。一時ファイルへ書き込み後にリネームする方式へ変更した。

13. **Makefile の実装**
    空ファイルであったため、`build.sh` と同等の内容を追加した。

14. **メトリクス履歴の保持期間**（`cmd/dashboard/main.go`）
    仕様では「直近約1時間」とされているが、実際には約12分しか保持できていなかった。また、`SystemStatus` 全体を保持していたためメモリ効率が悪かった。保持するデータを軽量なサンプル（時刻・CPU・メモリ・ディスクのみ）に変更し、保持件数を 3600 件（1秒間隔で約1時間）に修正した。

15. **空スクリプトの実装**
    `scripts/build.sh`、`scripts/dev.sh`、`scripts/lint.sh` が空であったため、それぞれ実装した。

## 5. 9月28日に検出・修正した問題

1. **読み取り専用ユーザーによるアラート履歴の削除**（`internal/auth/middleware.go`、`web/static/index.html`）
   権限判定がパスの接頭辞のみで行われていたため、閲覧のみの viewer が `DELETE /api/alerts` を実行でき、監査証跡を消去できた。判定にメソッドを追加し、削除は operator 以上に限定した。あわせて画面の削除ボタンにも権限表示を付与した。

2. **operator がモジュール管理を行えない**（`internal/auth/middleware.go`）
   `/api/plugins` が admin 限定であったため、operator が仕様どおりの「モジュール管理・手動実行」を行えなかった。参照と手動実行は operator、アップロードと削除は admin のままとした。

3. **ブラウザによる偽ステータスの注入と Agent の乗っ取り**（`cmd/dashboard/main.go`）
   ステータスの受信処理が Agent かどうかを確認していなかったため、ログイン済みの viewer が偽のステータスを送信して保存値を上書きできた。また、トークン未設定時には Agent を騙って接続を乗っ取り、偽のセキュリティ通知を発生させることができた。Agent 以外のペイロードを拒否する判定を追加し、昇格は非ブラウザのクライアントに限定した。

4. **認証無効時の管理者作成**（`internal/auth/handlers.go`）
   認証が無効でユーザーが未作成の状態では、ネットワーク上の誰でも `/api/auth/setup` で管理者を作成できた。後から認証を有効にすると、そのアカウントが正規の管理者として残る恐れがあった。認証が無効な場合はセットアップを拒否するよう修正した。

5. **`users.json` の git 管理漏れ**（`.gitignore`）
   パスワードハッシュを保持する `users.json` が無視対象に含まれておらず、誤ってコミットされる恐れがあった。無視対象に追加した。
