## 第101章: HMAC 鍵の管理（既知の課題・追記）

V1-A で導入したチェーン鍵 /samba/share/Kizuna-Eye/keys/chain.key の運用課題。

### 101-1. 鍵のバックアップ

- 鍵を失うと既存チェーン（kizuna-security.log）の検証が全行 mismatch になる。
- 鍵は 0600 で保護。バックアップは、アクセス制御された別ストレージ（Samba外・権限600）に取得する。
- バックアップ先も本番と同等に保護する（鍵の漏洩は改ざん検知の無効化に直結）。
- 鍵を紛失した場合の復旧手順: 現行ログを .legacy-<ts> に退避し、新鍵で新チェーンを開始する（既存 NewFileLoggerKeyed の退避ロジックが自動で行う）。ただし退避前のログは「検証不能な旧ログ」となる。

### 101-2. 鍵のローテーション

- 鍵を定期的に更新したい場合: 新鍵を chain.key.new に用意し、ログを .legacy-<ts> に退避 → 新鍵でチェーン継続、の手順。
- ローテーションは「検証不能期間」を作らないよう、退避と新鍵配置を連続して行う。
- 自動ローテーションは未実装。手動運用。

### 101-3. 既知の限界

- agent と攻撃者が同一ユーザー権限の場合、鍵（0600 だが agent が読める）も読めるため、HMAC を偽装できる。完全防御には agent 専用ユーザー化（B）が必要。
- 鍵の漏洩検知（誰が読んだか）は未実装。
