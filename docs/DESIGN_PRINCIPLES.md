# Kizuna-Eye 実装のこだわり

> この文書は「なぜそう書いたか」を残すためのもの。仕様（何をするか）は
> 仕様書に、こだわり（どう書くか・なぜそう書くか）はここに置く。

---

## 0. 大原則

**安全・堅牢・簡単。** 迷ったら「安全側（fail-closed）」に倒す。
壊れるくらいなら、断る。

---

## 1. 状態の変化は「原子的」に書く

設定・ベースライン・状態ファイルは、書きかけの状態を誰にも見せない。

- 一時ファイルに書く → `fsync` → `rename`（`pkg/fsutil.WriteFileAtomic`）。
  クラッシュしても「半端な設定」が残らない。
- **シンボリックリンクは拒否する**。書込先が攻撃者に差し替え可能な
  ディレクトリ（Samba 共有など）にあるとき、symlink を辿ると任意ファイルを
  書けてしまう（CWE-59）ため、fail-closed で断る。
- パーミッションは `rename` の**前**に付ける。一瞬でも「緩い権限のファイル」が
  存在しないように。
- 同じ処理が12箇所に散っていたのを1つに集約（L-12）。コピペは必ず腐る。

## 2. 秘密と権限は「1つずつ」

- **1鍵1用途**。チェーン鍵（`chain.key`）とアラート履歴署名鍵
  （`alert_history.key`）は別物。片方が漏れても、もう片方の改ざん検知は生きる。
- 鍵・状態ファイルは `0600`。ただし **A-4（agent 専用ユーザー）では group read
  が必要**なものだけ `0640` にし、理由をコードに書く。無条件に締めると、
  agent が読めずに「無言で」機能が落ちる。
- 権限が緩い鍵を見つけたら**警告**する（`warnChainKeyPermissions`）。
  ただし一度きりではなく**間隔を空けて再警告**し、直れば記録を消す
  （`sync.Once` だと直した後の再発に気づけない）。

## 3. 「無言の失敗」を絶対に許さない

一番怖いのは、**動いているように見えて動いていない**状態。

- S.M.A.R.T が権限不足で読めないとき → 起動時と収集時に**一度だけ警告**。
  `smartctl --scan` の成否で「可用」と誤判定しない（--scan は権限が無くても成功する）。
- cron 監視で**読めないディレクトリ** → `checkUnreadable` で警告。
  `filepath.WalkDir` のエラーを `return nil` で握りつぶさない。
- プラグインがロード失敗 → `module_status` でダッシュボードへ伝え、
  カードを「監視中」ではなく「読み込み失敗」で表示。
- 検査失敗の理由が空 → それはバグ。`plugin-inspect` は理由を **STDOUT の
  JSON** に出すので、**STDOUT を読む**（STDERR だけ見て空文字を出していた）。

## 4. 信頼できないものは「数えない・繋がない・残さない」

### ログ偽造
- `pkg/logsafe.Field` は CR/LF/TAB を**空白ではなく削除**する。空白だと
  `user=a [INFO] FORGED` のように偽タグが読めてしまう。
- `[` `]` はエスケープし、`[WARN]` の偽装を防ぐ。

### ログのハッシュチェーン
- 鍵なし SHA-256 → 改ざん権限で再計算できた（V1）。**HMAC-SHA256 に変更**し、
  **定期検証**（5分ごと）を追加。
- チェーンでは検知できない**末尾削除**は、**行数最大値**を状態ファイルに記録して
  検知（`checkLogMonotonic`）。

### アラート履歴
- 改ざんされ得る `security_*`（ログ由来）は `trusted=false`。
  ダッシュボード自身が出したものは `trusted=true`。
- 履歴が溢れたら、**信頼度とレベル重みの低いものから**捨てる。偽アラートの大量
  投入で本物が押し出されないように。

## 5. 「カードはモジュールが追加する」

設計書 5.4 のとおり、カードの中身（HTML/JS/CSS）は**モジュール側**が持つ。
コアは**汎用の iframe 枠**だけを出す。

- `pkg/module.WebAssetProvider`（`WebUIPath` / `WebAssets`）でモジュールが UI を申告。
- `plugin-inspect --web-out` が展開。**絶対パス・`..`・`\` は拒否**し、
  UI ルート外へ書けない。
- `index.html` にカードを固定しない。有効なモジュールが宣言している間だけ、
  履歴の直上に iframe 枠を生成する。
- 集計（`pkg/insight`）は**コア**に残す。「見せ方＝モジュール、計算＝コア」。

## 6. fail-closed の徹底

| 場面 | 挙動 |
|---|---|
| admin 判定が未配線（nil） | 変更を**拒否**（403） |
| 署名が必要なのに鍵が無い | 起動を**拒否** |
| bwrap が無い | 検査を**拒否**（無防備実行に落とさない） |
| プラグインの origin が証明できない | **sandbox 扱い** |
| `require_signature=true` + 鍵なし を保存 | **400 で拒否**（次の起動で死なせない） |

## 7. 権限は「できる操作だけ」を見せる

- operator にできない操作のボタンは**出さない**（押して 403 になる UX を避ける）。
- モジュールの有効/無効・削除・追加（コード実行境界）は **admin のみ**。
- 保護・復旧に直結するフィールド（`plugin_path` / `chain_key_path` 等）の変更も
  **admin のみ**。運用調整（間隔・閾値）は operator のまま。

## 8. i18n は「キーの一致」を機械で守る

- ja/en のキー数一致を**Go テスト**と `check_i18n.js` で固定。
- API は**文字列を返さない**。`reason_code` などの**機械可読なコード**を返し、
  文言はフロントで翻訳する。サーバーの日本語エラーが UI に漏れない。
- ログは JSON Lines（`message` + `message_en`）。言語切替でログ本文も追従。

## 9. プラグイン ABI の掟

- 共有パッケージ（`pkg/module` / `pkg/status` / `pkg/fsutil`）を変更したら、
  **agent と全 `.so` を同一ソース・同一ツールチェーンで同時再ビルド**。
  片方だけだと `plugin was built with a different version of package` で全滅。
- **`-trimpath` を host と全 plugin で必ず同じ設定にする**（現在は常時 ON）。片方だけ付けるとハッシュがずれるが、両方に付けば build ID がパス非依存になり、ビルドしたユーザー（sudo/root か user か）に依存せず一致する。
- **モジュール解決の方法も一致させる**。ホストは `go.work`、プラグインは `GOWORK=off`（=プラグイン側の `replace Kizuna-Eye => ...`）でビルドすると、同じソース・同じツールチェーン・同じ `-trimpath` でも共有パッケージの build ID が食い違い、`plugin was built with a different version of package Kizuna-Eye/pkg/fsutil` でロードできない（2026-10-10 に実機で発生）。**ホストと全プラグインを 1 つの combined go.work（`use` にホスト＋各プラグインディレクトリを列挙）の下でビルドする**。`build-all.sh` / `update.sh` / `scripts/build-plugin.sh` はすべてこの方式に統一済み。
- **ツールチェーンはパッチまで固定**（`toolchain go1.27.2`）。
- 一度 `Open` した `.so` は再 `Open` できない（Go の制約）。→ **コンストラクタを
  キャッシュ**して、無効化→有効化を**再起動なし**で行えるようにした。
  `.so` を差し替えた場合だけ再起動が要る。

## 10. 小さく速く、低スペックでも動く

- 目標は「A4-4020 / 4.5GB で軽快」。`-s -w` でバイナリを約3割縮小。
- `GOGC=50` / `GOMEMLIMIT=64MiB` / `GODEBUG=madvdontneed=1`。
- Go プラグインの cgo 依存は重いが、ABI 一致の安全性を優先。

## 11. 失敗の「証拠」を残す

- SIGSEGV 時に全 goroutine のスタックを残す（`GOTRACEBACK=crash`）。
- プラグインのロード失敗理由は `reason_code` + 生メッセージの両方。
- 証拠保全は秘密情報を含むため **Samba 外・0600**。

## 12. 「テストできないものは信用しない」

- 署名方式（append / body swap）は**テストで拒否を証明**。
- 署名検証・改ざん検知・パストラバーサル・ReDoS 耐性は回帰テスト付き。
- プラグインのペイロード（Discord/LINE）は**形をテストで固定**し、
  静かに壊れるのを CI で検知。

## おわりに

これらは「かっこいいから」ではなく、**実際に踏んだバグと攻撃**から来ている。
記録に残っている失敗（デッドロック、ABI 不一致、無言の故障、偽アラート）を
二度と繰り返さないための知恵。迷ったらこの文書に戻る。
