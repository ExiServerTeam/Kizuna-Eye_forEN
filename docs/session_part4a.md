## 第71章: FIM誤検知調査

### 71-1. 発端

フェーズ1の起動直後（01:24）に「/etc/group が変更されました」の critical アラートが出た。誤検知か実変更かを確認した。

### 71-2. 調査結果

/etc/group- （Sep4, 954B）と /etc/group（Oct2, 950B）の差分:

docker:x:108:user  →  docker:x:108:

（user が docker グループから外れた＝正当な変更）

### 71-3. 判定: 誤検知ではない（遅延した真の検知）

時系列:
1. 10/2 06:57 — /etc/group が実際に変更
2. 10/2 06:57〜10/3 01:23 — fim.go デッドロックで FIM 停止（ベースライン未更新）
3. 10/3 01:23 — デッドロック修正
4. 10/3 01:24 — FIM復活、旧ベースラインとの差分を検知

FIM は正しく動作。19時間の検知遅延があっただけ。現在はハッシュ一致＝再ベースライン済み。**ベースライン更新は不要**（既に更新済み）。

### 71-4. 学び

FIM はベースライン差分方式のため、**デッドロック等で停止すると、その間の変更が復旧時にまとめて検知される**。これは「誤検知」ではなく「遅延検知」。FIM の稼働監視（heartbeat）があると、停止を早期に気づける。
